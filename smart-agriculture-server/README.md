# 智慧农业管理系统后端（比赛版）

## 1. 项目定位

本模块是“智慧农业管理系统”比赛项目后端，采用前后端分离架构，当前以“可运行、可演示、可扩展”为目标，重点突出：

- 智慧农业业务管理
- 环境监测与预警
- AI 分析联动
- 预警闭环处理流程

---

## 2. 当前已实现功能

### 2.1 基础能力

- Java 17 + Spring Boot 3 + Maven
- MyBatis-Plus + MySQL
- JWT 登录认证（单管理员场景）
- 统一返回结构 `Result`
- 全局异常处理
- 参数校验（Spring Validation）
- OpenAPI / Swagger 本地接口文档

### 2.2 业务模块

- 管理员：登录、当前用户信息、密码修改
- 农田管理：新增/编辑/删除/详情/分页
- 作物管理：新增/编辑/删除/详情/分页与条件筛选
- 设备管理：新增/编辑/删除/详情/分页与状态筛选
- 环境监测：数据录入、分页查询、趋势查询、图表数据输出
- 首页看板：汇总指标、分布统计、趋势数据
- AI 助手：问答、分析接口、记录保存

### 2.3 智能预警闭环中心（本轮重点）

已从“普通预警列表”升级为“预警闭环流程”：

1. 自动预警生成（第一版规则）
   - 土壤湿度过低
   - 温度过高 / 过低
   - 光照异常
   - 设备离线
2. 预警状态流转
   - 待确认 -> 处理中 -> 已处理 -> 已闭环
   - 支持误报标记
3. 流转日志追踪
   - 记录动作、前后状态、操作人、时间、说明
4. AI 预警分析
   - `/ai/warning/analysis`
   - `/ai/warning/disposal`
   - 支持结构化输出与 mock 兜底
5. 闭环字段落库
   - `warning` 主表扩展字段
   - `warning_process_log` 处理日志表
   - `warning_ai_analysis` AI 分析记录表

## 3. 数据库与迁移说明

### 3.1 新增/升级脚本

- `src/main/resources/db/migrate_warning_closure_center.sql`
- `src/main/resources/db/init_warning.sql`
- `src/main/resources/db/init_real_china_competition_data.sql`

### 3.2 自动兼容迁移

为避免旧库缺字段导致 500（如 `warning_no` 缺失），已加入启动迁移器：

- `com.smartagri.config.WarningSchemaMigrationRunner`
- 配置项：`smart-agri.warning.auto-migrate-closure-schema=true`

后端启动时会自动补齐 `warning` 闭环字段，并创建日志/AI分析子表。

## 4. 仍可继续升级的方向

### 4.1 业务能力升级

- 预警规则中心化配置（按作物/农田差异化阈值）
- 定时批量扫描任务（分钟级自动巡检）
- 预警通知通道（短信/企业微信/邮件）
- 处置 SOP 模板库（按预警类型自动匹配）

### 4.2 AI 能力升级

- 接入真实大模型（OpenAI / Spring AI）
- 引入 RAG 农业知识库（病虫害、栽培手册）
- 结构化报告导出（日报/周报）
- AI 建议效果追踪（建议执行率、闭环时长）

### 4.3 工程化升级

- 使用 Flyway / Liquibase 管理数据库版本
- 增加单元测试与集成测试
- 增加接口幂等和审计日志
- 增加监控指标（慢 SQL、预警处理耗时）

---

## 5. 本地运行建议（闭环中心）

1. 启动 MySQL 并创建库 `smart_agriculture`
2. 导入基础脚本（或直接启动后端自动迁移旧库）
3. 启动后端服务
4. 访问 Swagger 验证以下接口：
   - 预警分页/详情
   - 预警流转
   - AI 分析与处置建议

---

## 6. 比赛答辩可用总结

当前系统已具备“异常识别 -> 自动预警 -> AI研判 -> 处置流转 -> 闭环归档 -> 看板展示”的完整链路，不再停留在基础 CRUD，可作为“智慧农业 + AI + 业务闭环”核心亮点演示。
