# 端到端联调与测试手册

本文档用于在本机**独立复现**全链路验证：MySQL ↔ Spring Boot ↔ Vue 前端 ↔（可选）rag-service ↔（可选）Qdrant / Neo4j。  
按顺序执行即可；每步给出**预期现象**，便于判断模块是否已正确连通。

> **说明**：以下命令在 **Windows PowerShell** 下编写；若使用 **cmd** 或 **Git Bash**，请将 `Invoke-RestMethod` 换为等效的 `curl`（示例见 §6.2）。

---

## 1. 数据库初始化

### 1.1 创建库

在 MySQL 中执行（库名需与后端 `application.yml` 中 `spring.datasource.url` 一致，默认如下）：

```sql
CREATE DATABASE IF NOT EXISTS smart_agriculture
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

### 1.2 导入脚本（建议顺序）

在 `smart-agriculture-server/src/main/resources/db/` 目录下，按依赖关系执行（若已存在表与数据，注意备份）。当前仓库内脚本包括：

| 文件 | 说明 |
|------|------|
| `init_admin.sql` | 管理员表与默认账号 |
| `init_field.sql` | 农田 |
| `init_crop.sql` | 作物 |
| `init_device.sql` | 设备 |
| `init_environment_data.sql` | 环境数据 |
| `init_warning.sql` | 预警 |
| `init_warning_rule_config.sql` | 预警规则配置 |
| `init_ai_chat_log.sql` | AI 对话日志表结构 |
| `init_inspection_task_log.sql` | 巡检任务日志 |
| `migrate_warning_closure_center.sql` | 预警闭环相关迁移 |
| `init_real_china_competition_data.sql` | 一次性灌入较全样本数据（含 `DELETE FROM admin` 后重建，**慎用**于已有环境） |

建议顺序：**先 `init_admin.sql`，再农田/作物/设备/环境，再预警与规则**，最后按需执行迁移与样本数据。

若仅验证登录与列表，**至少执行 `init_admin.sql`**。

### 1.3 默认管理员账号（来自 `init_admin.sql` / 种子数据）

| 字段 | 值 |
|------|-----|
| 用户名 | `admin` |
| 密码（明文） | `123456` |

密码在库中为 BCrypt 存储；若登录失败，请确认执行的是项目自带 `init_admin.sql` 或 `init_real_china_competition_data.sql` 中的同一哈希。

### 1.4 后端数据源配置

确认 `smart-agriculture-server/src/main/resources/application.yml` 中：

- `spring.datasource.url` 指向你的实例与库名  
- `username` / `password` 正确  

修改后需**重启** Spring Boot。

## 2. 配置文件核对（联调关键）

### 2.1 Spring Boot

- **`smart-agri.rag.base-url`**：默认 `http://localhost:9001`，须与 rag-service 实际地址一致。  
- **`smart-agri.rag.enabled`**：为 `true` 时才会调用 FastAPI；为 `false` 时走本地逻辑（见该模块实现）。  
- **`smart-agri.rag.fallback-enabled`**：为 `true` 时，FastAPI 不可用可由 Spring 返回兜底结构化结果。  
- **`smart-agri.knowledge-graph.*`**：使用图谱功能时，Neo4j URI、账号密码需与实例一致。

### 2.2 rag-service（`rag-service/.env`）

从模板复制：

```bash
cd rag-service
copy .env.example .env
```

**在未启动 Qdrant 时**，必须保证（否则 `/rag/answer` 可能因无法连接向量库而 500）：

```env
KNOWLEDGE_RETRIEVAL_FALLBACK_TO_MOCK=true
```

**在未配置大模型 API Key 时**，建议：

```env
LLM_FALLBACK_TO_MOCK=true
```

若已配置 `OPENAI_API_KEY` 且 Qdrant 已就绪，可将上述两项设为 `false` 以走真实检索与模型。

修改 `.env` 后需**重启** `uvicorn`。

### 2.3 前端

开发环境默认通过 `VITE_APP_BASE_API` 指向后端；未设置时使用 `http://localhost:8080/api`（见 `smart-agriculture-web/src/utils/request.js`）。若后端端口或网关路径不同，请设置：

```text
# smart-agriculture-web/.env.development
VITE_APP_BASE_API=http://localhost:8080/api
```

## 4. 服务启动顺序（推荐）

1. **MySQL**（系统服务或手动启动）  
2. **Spring Boot**  
3. **rag-service**（若需 AI 助手完整链路）  
4. **（可选）Qdrant** — 未启动时须开启 §2.2 检索兜底  
5. **（可选）Neo4j** — 复制 `.env.docker.neo4j.example` 为 `.env.docker.neo4j` 后，执行 `docker compose -f docker-compose.neo4j.yml up -d`；Spring 设置 `SMART_AGRI_NEO4J_PASSWORD` 与 `NEO4J_AUTH` 密码一致。  
6. **Vue** — `npm run dev`

### 4.1 启动 Spring Boot

```powershell
cd smart-agriculture-server
mvn spring-boot:run
```

**预期**：控制台无数据源连接失败；出现类似 `Started ...Application`；可访问：  
`http://localhost:8080/api/swagger-ui.html`

### 4.2 启动 rag-service

```powershell
cd rag-service
python -m uvicorn app.main:app --host 0.0.0.0 --port 9001 --reload
```

**预期**：`http://127.0.0.1:9001/docs` 可打开；`GET http://127.0.0.1:9001/health` 返回 JSON 且 `code` 为 `0`。

### 4.3 启动前端

```powershell
cd smart-agriculture-web
npm run dev
```

**预期**：终端打印本地 URL（通常为 `http://localhost:5173`）。

## 5. 接口自动化验证（真实返回数据）

以下接口返回的 `code`、字段名以你当前代码为准；**成功时 Spring 统一包装一般为 `code: 200`，rag-service 为 `code: 0`**。

### 5.1 rag-service 健康检查

**PowerShell：**

```powershell
Invoke-RestMethod -Uri "http://127.0.0.1:9001/health" -Method Get | ConvertTo-Json -Depth 5
```

**预期**：`code` 为 `0`，`data.status` 为 `UP` 或类似表示运行中。

### 5.2 rag-service 问答（不经过 Spring）

**PowerShell（UTF-8 请求体，避免中文乱码）：**

```powershell
$body = '{"query":"土壤湿度长期偏低有什么农业风险","mode":"knowledge"}'
Invoke-RestMethod -Uri "http://127.0.0.1:9001/rag/answer" -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes($body)) | ConvertTo-Json -Depth 6
```

**预期**：`code` 为 `0`；`data` 中含 `answer_summary`、`conclusion`、`recommendations` 等字段；内容为真实生成的字符串（mock 或模型输出）。

若返回 **500**：检查 Qdrant 是否未启动且 `KNOWLEDGE_RETRIEVAL_FALLBACK_TO_MOCK` 是否为 `false`；按 §2.2 修改后重启。

### 5.3 Spring 登录（获取 Token）

```powershell
$loginBody = '{"username":"admin","password":"123456"}'
$login = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/auth/login" -Method Post `
  -ContentType "application/json" -Body $loginBody
$token = $login.data.token
$login.code
```

**预期**：`code` 为 `200`；`$token` 非空。

### 5.4 Spring 当前用户信息（需鉴权）

```powershell
$h = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/auth/me" -Headers $h | ConvertTo-Json -Depth 5
```

**预期**：`code` 为 `200`；`data` 中含当前管理员用户名等信息。

### 5.5 Spring RAG 对话（全链路：Spring → rag-service）

```powershell
$ragBody = @{
  query = "当前土壤湿度相关风险有哪些"
  mode  = "knowledge"
} | ConvertTo-Json
$rag = Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/ai/rag/chat" -Method Post `
  -ContentType "application/json; charset=utf-8" `
  -Headers $h -Body ([System.Text.Encoding]::UTF8.GetBytes($ragBody))
$rag.code
$rag.data.answerSummary.Substring(0, [Math]::Min(120, $rag.data.answerSummary.Length))
```

**预期**：`code` 为 `200`；`data.answerSummary` 等为非空字符串。  
若 rag-service 未启动且 Spring 已开启 RAG 兜底，仍可能返回结构化兜底内容（`fallback` 等字段见 VO 定义）。

### 5.6 业务列表接口抽样（验证 MyBatis ↔ 数据库）

```powershell
# 农田分页（Controller 映射为 /fields/page）
Invoke-RestMethod -Uri "http://127.0.0.1:8080/api/fields/page?current=1&size=5" -Headers $h | ConvertTo-Json -Depth 4
```

**预期**：`code` 为 `200`；`data.records` 为数组（可为空，但不应为 SQL 异常）。

> 其他模块路径请以 `http://localhost:8080/api/swagger-ui.html` 为准。

### 5.7 curl 等价示例（Git Bash / Linux / macOS）

```bash
curl -s http://127.0.0.1:9001/health | jq .

curl -s -X POST http://127.0.0.1:9001/rag/answer \
  -H "Content-Type: application/json; charset=utf-8" \
  -d '{"query":"土壤湿度偏低有什么风险","mode":"knowledge"}' | jq .

TOKEN=$(curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | jq -r '.data.token')

curl -s http://127.0.0.1:8080/api/auth/me \
  -H "Authorization: Bearer $TOKEN" | jq .
```

## 8. 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 登录 401 / 网络错误 | 后端未启动或端口错 | 检查 8080、`context-path` |
| RAG 问答 500（FastAPI） | Qdrant 未起且未开检索兜底 | §2.2 设置 `KNOWLEDGE_RETRIEVAL_FALLBACK_TO_MOCK=true` |
| Spring 调 RAG 失败 | 9001 未监听或 URL 错误 | 检查 `smart-agri.rag.base-url` |
| 图谱页面异常 | Neo4j 未启动或密码错误 | 检查 `.env.docker.neo4j` 与 `SMART_AGRI_NEO4J_PASSWORD` |
| 前端跨域 | 开发环境通常由 Vite 代理；直连 file 打开会 CORS | 使用 `npm run dev` 访问 |

## 9. 联调通过标准（建议）

满足下列即可认为「模块已正确联系起来」：

1. `mvn compile` 与 `npm run build` 均无错误。  
2. `POST /api/auth/login` 返回 `200` 且 token 可用；`GET /api/auth/me` 成功。  
3. `GET /health`（rag-service）成功；在 Qdrant 未启动时，`POST /rag/answer` 在兜底开启下仍返回 `code:0` 与完整 `data`。  
4. `POST /api/ai/rag/chat`（带 Token）返回 `200` 且含摘要等字段（或明确兜底标记）。  
5. 浏览器端主要菜单均可打开且无持续性 500。
